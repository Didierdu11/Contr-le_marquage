Changement du numéro de lot

Le n° du jour du lot change à 00h00 + ce décalage. Exemples : −5 → 19h00 la veille ; −4,5 → 19h30 la veille ; 0 → 00h00 ; +2 → 02h00. La valeur est mémorisée dans l'application.

Boutons du contrôle

Décochés par défaut. Le bouton « Scan lot » est toujours affiché.

Cadre de prise de photo

Ce cadre apparaît en surimpression quand vous prenez la photo (aperçu ci-dessus, en proportion de l'écran). Seule la zone du cadre est lue. Valeurs mémorisées.

Moteur de lecture

PaddleOCR demande 2 fichiers déposés à côté de index.html : model.onnx (7,8 Mo) et dict.txt (1,4 Ko). Liens et marche à suivre : voir la Notice.

Historique

Quand vous changez de produit, les enregistrements du produit précédent sont exportés en Excel, puis rangés dans une série repliable. Seules les N dernières séries sont conservées (3 par défaut) : les plus anciennes sont supprimées avec leurs photos.

Contrôle de l'heure

Quand le type de marquage imprime une heure, elle est comparée à l'horloge de l'appareil avec cette tolérance. Valeur mémorisée.

Notice

Notice d'utilisation

  1. Paramètres : le bouton ⚙️ ouvre une page à part (bouton « ← Retour » pour revenir). Vous y choisissez le fichier Excel, réglez le décalage du n° de lot et la tolérance de l'heure. Ces réglages restent mémorisés tant que vous ne les modifiez pas.
  2. Fichier Excel : feuilles « Produits » et « Types de marquage ». Rechargez-le dans les Paramètres après chaque modification. Dans Excel, la feuille « Calcul » a une case « Décalage » : saisissez la même valeur que dans l'application pour que le texte attendu soit identique. Le résumé (date de chargement, nombre de produits et de types) s'affiche à côté du type.
  3. Changement de n° de lot : le n° du jour change à 00h00. Le décalage (en heures, + ou −) déplace cet instant : −5 → 19h00 la veille ; −4,5 → 19h30 la veille ; +2 → 02h00. L'heure exacte du changement est rappelée sous le champ.
  4. Tolérance de l'heure : quand le type imprime une heure, elle doit être à ± N minutes de l'horloge de l'appareil. N se règle dans les Paramètres (10 par défaut).
  5. Opérateur et produit : saisissez votre nom puis choisissez le produit. Son type de marquage s'affiche dessous.
  6. Aperçu : dans « Contrôle », le cadre blanc montre exactement ce que le carton doit afficher maintenant (lot, date, heure). L1, L2… = lignes du carton. ↵ / ↳ indique la suite de la même ligne, coupée faute de place.
  7. Photo : « 📷 Scan lot » ouvre la caméra avec un cadre jaune en surimpression. Placez le marquage dans le cadre, de près et net, touchez « 📸 Prendre la photo », puis « ✅ Valider » (ou « ↺ Reprendre »). La lecture de la zone du cadre et la vérification démarrent alors toutes seules : vous arrivez sur la zone de contrôle avec le résultat. Largeur et hauteur du cadre se règlent dans les Paramètres. Les boutons « Saisie manuelle » et « 🖼️ Importer une photo » sont masqués par défaut : cochez-les dans les Paramètres pour les afficher.
  8. Cadre (si besoin de le modifier) : « ↩ Redessiner le cadre » ou après une importation, entourez du doigt uniquement le marquage, puis « 🔍 Lire la zone » (boutons toujours visibles en bas). L'écran montre : ① ce que vous devez avoir, ② la zone encadrée, ③ ce que l'application lit. Corrigez le texte si besoin puis « Vérifier et enregistrer ».
  9. Marquage en points : utilisez « 🧪 Comparer à l'image attendue ». Vert = point attendu trouvé, rouge = point manquant, bleu = point en trop. « 👁 Masquer les points » laisse la photo d'origine. Réglez au besoin sensibilité, largeur des lettres et écarts, puis choisissez ✅ Conforme ou ❌ Non conforme.
  10. Saisie manuelle (bouton à activer dans les Paramètres) : recopiez le texte du marquage ; la vérification et les boutons de validation s'affichent comme pour un scan.
  11. Lecture automatique : l'application fait plusieurs essais à des tailles différentes et retient le lot le plus souvent lu. Si l'heure reste incertaine (chiffres petits), un avertissement s'affiche : contrôlez-la sur la photo.
  12. Heure lue : les 4 chiffres lus juste après le lot sont pris pour les heures et minutes, même s'ils sont lus O, o, Q, D ou U (comptés comme 0) ou I (compté comme 1) : « oo 52 » devient 00:52, « 04.01 » devient 04:01.
  13. Résultat : sous les 3 zones (① attendu, ② zone encadrée, ③ lu), un bouton vert « ✅ Scan conforme » apparaît si tout correspond : il enregistre le contrôle « validé en auto ». Sinon le message rouge « Scan non conforme » donne la raison, avec le bouton orange « Valider après confirmation visuelle » : après avoir regardé le carton, il enregistre le contrôle « validé manuellement » (repris dans l'onglet Anomalies de l'export). Le bouton « Enregistrer comme non conforme » enregistre un carton réellement erroné. Corriger le texte ③ relance la vérification.
  14. Séries et export : tant que vous restez sur le même produit, ses enregistrements restent dans « En cours ». Quand vous changez de produit, l'application exporte automatiquement en Excel les enregistrements du produit précédent (un fichier : onglets Contrôles, Statistiques, Anomalies) puis les range dans une liste repliable « Séries exportées », repérée par produit et lot. Seules les 3 dernières séries sont conservées (réglable dans les Paramètres). Le bouton « Exporter les enregistrements en cours » fait une copie Excel sans changer l'historique ; « Exporter à nouveau » refait l'export d'une série.

Fichier Excel : colonne « Texte modèle » avec les mots-clés {DATE}, {LOT}, {HEURE} et {*} (texte quelconque). Avec {*}, la comparaison d'image n'est pas possible.

Installer PaddleOCR (lecture locale, gratuite) — 2 fichiers à déposer

  1. Télécharger (téléphone ou PC, un clic lance le téléchargement) :
    ① model.onnx (7,8 Mo) : huggingface.co/xberg-io/paddleocr-onnx-models/resolve/main/rec/english/model.onnx?download=true
    ② dict.txt (1,4 Ko) : huggingface.co/xberg-io/paddleocr-onnx-models/resolve/main/rec/english/dict.txt?download=true
    Ces deux fichiers vont ensemble (même dossier « rec/english » du dépôt). Ne changez pas leurs noms.
  2. Déposer : dans votre dépôt GitHub (celui de didierdu11.github.io), au même endroit que index.html (à la racine, à côté de manifest.json et sw.js). GitHub : bouton « Add file » → « Upload files », choisissez les deux fichiers, puis « Commit changes ». Un dossier n'est pas nécessaire (un dossier « models » est aussi accepté).
  3. Attendre environ 1 à 2 minutes que GitHub Pages publie, puis ouvrez l'application avec internet.
  4. Vérifier : ⚙️ Paramètres → « Tester PaddleOCR ». Message attendu : ✅ PaddleOCR prêt, avec le texte lu pour une phrase d'essai.

Le modèle lit des lignes recadrées : entourez bien le marquage. Solution de secours si ces liens changent : fichiers en_PP-OCRv3_rec_infer.onnx (huggingface.co/SWHL/RapidOCR, dossier PP-OCRv3) et en_dict.txt (dépôt PaddleOCR, ppocr/utils/en_dict.txt), à renommer en model.onnx et dict.txt.

Installer l'application sur le téléphone : ouvrez la page avec Chrome, menu ⋮ → « Installer l'application » (ou « Ajouter à l'écran d'accueil »). Sur iPhone : Safari → Partager → « Sur l'écran d'accueil ». L'icône « Contrôle marquage » apparaît ensuite avec les autres applications. Le produit choisi est mémorisé même après fermeture.

Bon à savoir : les données restent sur l'appareil (enregistrements en cours et dernières séries exportées). Connexion internet requise à la première ouverture.
